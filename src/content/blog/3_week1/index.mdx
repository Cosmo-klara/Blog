## Record

### 本周工作


+ [Fit and Prune: Fast and Training-free Visual Token Pruning for Multi-modal Large Language Models](https://arxiv.org/abs/2409.10197)

    这篇工作把视觉 token 剪枝建模为“保持注意力分布不变”的拟合问题，在给定预算下寻找对自注意力和交叉注意力分布影响最小的剪枝方案。它最大的优点是 training-free，只需要基于少量推理样本统计注意力信息，就能很快生成分层剪枝 recipe。对我来说比较有启发的一点是，可以把“最小化后续层分布扰动”作为设计剪枝准则，而不一定一开始就依赖额外训练。

+ [LLaVA-Zip: Adaptive Visual Token Compression with Intrinsic Image Information](https://arxiv.org/abs/2412.08771)

    LLaVA-Zip 关注的是视觉 token 过多导致上下文窗口被占满的问题，提出基于图像内在信息量的动态压缩方式，对不同输入自适应地保留不同数量的视觉特征。它不是简单地固定压缩率，而是尝试根据输入复杂度来决定保留多少 token。这个思路对后续做自适应预算分配很有参考价值，尤其适合多图像或长视频场景下的前端压缩。

+ [VScan: Rethinking Visual Token Reduction for Efficient Large Vision-Language Models](https://arxiv.org/abs/2505.22654)

    这篇论文重新审视了 LVLM 中视觉 token reduction 应该发生在什么位置，提出了两阶段框架：先在视觉编码阶段结合 global/local scan 做 token merging，再在语言模型中间层进一步做 pruning。相比只在单一位置裁剪 token，它更强调“编码阶段压冗余 + 解码阶段去无关”的组合策略。这个分阶段思路和我现在考虑的“先保留关键跨模态信息，再在中后层集中剪枝”有一定呼应。

+ [OmniSIFT: Modality-Asymmetric Token Compression for Efficient Omni-modal Large Language Models](https://arxiv.org/abs/2602.04804)

    OmniSIFT 面向音视频联合输入的 Omni-LLM，核心是按照模态特性不对称地压缩 token：视频侧做时空冗余剪枝，音频侧则利用视觉引导选择更关键的音频 token。它说明了在 omnimodal 场景里，不同模态的冗余模式并不一致，因此不一定适合用同一种打分与保留策略。对我的启发是，音频 token 的处理也许应更多依赖跨模态关系，而不是完全照搬视觉 token 的重要性估计。

+ [Omni-Prune: Query-Aware Unified Token Pruning for Efficient Omnimodal Large Language Models](https://arxiv.org/abs/2607.23445)

    Omni-Prune 更进一步，把 query-aware 和跨模态联合建模结合起来，同时对音频和视频 token 进行统一剪枝。它通过音频显著性划分时间窗口，再结合文本查询相关性与跨模态耦合关系来打分，并尽量成对保留有关联的音视频 token。这个工作值得重点看，因为它强调“用户问题决定什么信息重要”，对后续设计任务相关的动态剪枝策略很有借鉴意义。
